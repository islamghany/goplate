# Adding a module

`internal/note` is the reference module: it shows every pattern once. This
guide walks through adding a `project` module the same way. Expect about
30 minutes for a CRUD module.

```mermaid
flowchart LR
    m[1. migration] --> q[2. queries + sqlc] --> d[3. domain + ports] --> s[4. service]
    s --> h[5. http] --> a[6. adapter] --> w[7. wire in cmd/api] --> o[8. OpenAPI] --> t[9. tests]
```

## 1. Migration

```bash
make migration name=create_projects
```

Edit `migrations/NNNNN_create_projects.sql`. Use `uuid` primary keys
(generated by the app as UUIDv7), `timestamptz` timestamps, and an index that
matches your list query (`(owner_id, created_at DESC, id DESC)` for keyset
pagination). Then `make migrate`.

Remember: migrations must be compatible with the **previous** release of the
code (expand/contract), because old pods keep serving during a rollout.

## 2. Queries

Create `internal/project/projectpg/queries.sql` and add a block to
`sqlc.yaml` (copy the `note` block, change `queries`, `package` and `out`).
Run `make generate`.

## 3. Domain types and ports: `internal/project/project.go`

- The `Project` type, and sentinel errors with a kind:
  `var ErrNotFound = errs.New(errs.NotFound, "project not found")`.
- The **ports** this module needs, as small interfaces: `Repository`, plus
  `Transactor`, `JobEnqueuer` or a cache only if you use them.
- If you need another module (for example, users), declare an interface here
  in your own terms. Don't import that module; you'll bridge it in step 7.
  To show its data alongside yours (a "join"), follow
  [cross-module-reads.md](cross-module-reads.md).
- Job argument types, if any (`Kind()` must never change once deployed).

This file imports only the kernel (`errs`, `identity`, `page`, `jobs`, …).
`make lint` fails otherwise.

## 4. Service: `internal/project/service.go`

- Get the caller with `identity.Require(ctx)` and scope every repository call
  to them.
- Validate inputs with `validate.New()` here, not in the handler.
- Use `tx.WithinTx` when you touch more than one row or enqueue a job.
- Truncate timestamps to microseconds (Postgres precision), so cursors
  round-trip exactly.

## 5. Transport: `internal/project/http.go` and `module.go`

- Request/response DTOs with JSON tags; never serialize domain types directly.
- Handlers: `web.Decode[T]` → service → `web.JSON`. Return errors; don't
  write them.
- `module.go`: `Deps`, `NewModule(deps, cfg)`, `Routes(protected *web.Router)`.

## 6. Adapter: `internal/project/projectpg/repository.go`

- Hold the `*postgres.TxManager`, never the pool; build queries with
  `New(r.txm.DB(ctx))` so they join transactions automatically.
- Map generated rows to domain types.
- Translate errors: `postgres.IsNoRows` → `ErrNotFound`,
  `postgres.UniqueViolation` → a `Conflict` error, anything else →
  `errs.Wrap(errs.Internal, "", err)`.
- Add `var _ project.Repository = (*Repository)(nil)`.

## 7. Wire it: `cmd/api`

In `app.go`:

```go
projects := project.NewModule(project.Deps{
    Repo: projectpg.NewRepository(txm),
    Tx:   txm,
    Log:  log,
}, project.Config{})
// riverjobs.Register(queue, projects.Service.HandleSomething) // if it has jobs
```

Add it to the `modules` struct and to `mountRoutes` in `http.go`. If it needs
another module, write a bridge in `adapters.go`.

If the module needs configuration, add a struct to `internal/config`, map it
to `project.Config` in `app.go`, and document the variables in
`.env.example`.

## 8. OpenAPI

Add the paths and schemas to `api/openapi.yaml`. `go test ./cmd/api` fails
until every route you registered is documented, and vice versa.

## 9. Tests

- `service_test.go`: fakes for your ports. See `internal/note/service_test.go`.
- `projectpg/repository_integration_test.go`: `//go:build integration`, a
  `TestMain` calling `testutil.Start`, one `testutil.CreateUser` per test.
- Add a scenario to `cmd/api/e2e_integration_test.go` if the flow crosses
  modules.

Run `make check`. Done.
